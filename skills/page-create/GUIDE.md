# page-create — 정본 절차 (GUIDE)

> **이 파일이 정본이다.** 설치된 스텁이 발동 시 `npx ie guide page-create` 로 매번 이 내용을 새로 연다.
>
> 페이지 갤러리는 **"설명만으로 초안을 조립하고 다듬어 완성한다"** 가 기본 경로인 도구다.
> 개발자는 Figma 나 드래그 편집기에 능숙할 필요가 없다 — 원하는 화면을 말로 설명하면 된다.

---

## 0. 경계 (먼저 확인)

- **컴포넌트를 새로 만들지 않는다.** 필요한 UI 가 레지스트리에 없으면 그 자리에 `Placeholder` 를
  두고 초안을 끝낸 뒤, 사용자에게 `/element-create` 로 만들어야 한다고 알린다.
- **다루는 파일은 페이지 하나뿐이다.** 레지스트리·컴포넌트 코드·설정은 읽기만 한다.
- 경로는 하드코딩하지 않는다 — `npx ie config --json` 의 `pagesDir` 를 본다.

---

## 1. 데이터 모델

페이지는 노드 트리다. **모든 노드에 유일한 `props.id` 가 있어야 한다** — 리뷰 피드백이 그 id 로
자리를 가리키고, 흐름이 그 id 에 화면 전환을 붙인다. id 를 바꾸면 그 연결이 끊긴다.

### 노드 3종

| 종류 | 예시 | 자식 |
| --- | --- | --- |
| 레이아웃 컨테이너 | `{"type":"Stack","props":{"id":"Stack-1","gap":24,"items":[…]}}` | **`props.items`** |
| 레이아웃 leaf | `{"type":"Heading","props":{"id":"H-1","level":1,"text":"제목"}}` | 없음 |
| 레지스트리 컴포넌트 | `{"type":"stat-card","props":{"id":"stat-card-1","title":"매출"}}` | 없음(props 로 구성) |

- 컨테이너: `Stack`(세로·`gap`) / `Row`(가로·`gap`·`align`·`justify`·`wrap`) / `Grid`(`cols`·`gap`) / `Frame`(`padding`)
- leaf: `Heading`(`level` 1~4·`text`) / `Text`(`text`·`muted`) / `Spacer`(`size`) / `Placeholder`(`label`·`height`)
- 자식은 **반드시 `props.items`** 에 둔다. `zones` 는 쓰지 않는다.

### 의미 태그 — 구조를 읽기 쉽게 남기는 장치

`_` 로 시작하는 prop 은 화면에 직접 그려지지 않고 **사람과 에이전트가 지목에 쓰는 신호**다.

| prop | 뜻 |
| --- | --- |
| `_label` | 자유 별칭. `"메인 SNB"` 처럼 사람이 부르는 이름 |
| `_role` | 영역 역할 — `header`·`navigation`·`main`·`footer`·`sidebar`(랜드마크) + `hero`·`section`·`toolbar`(조언용) |
| `_regionSticky` | `"sticky"` 면 header·sidebar 를 상단 고정 |
| `_locked` | 사람이 잠근 노드 — 구조 변경을 피한다 |
| `hidden` | 편집 중 숨김 |

> ★ **랜드마크 5종은 실제 DOM 구조를 바꾼다.** 최상위 컨테이너에 주면 렌더가 `<header>`·`<nav>`·
> `<main>`·`<footer>`·`<aside>` 로 방출한다. 같은 역할이 최상위에 둘 이상이면 첫 노드만 그 태그를
> 갖고 나머지는 `<div>` 로 내려간다(중복 랜드마크는 스크린리더 내비게이션을 흐린다).
> 명백한 영역에만 부여한다.

**규약:**

1. **의미 맵부터 만든다.** 고도화를 시작할 때 트리를 훑어 `_role`·`_label` 이 붙은 노드를 모아
   페이지 해부도를 파악한다.
2. **역할·별칭으로 지목을 해석한다.** `"내비게이션에 로그인 버튼 추가"` 같은 요청이 오면 불투명한
   id 가 아니라 `_role`·`_label` 로 대상을 찾는다.
3. **보존한다.** `_role`·`_label`·`_locked` 과 **노드 `id`** 는 사람의 의도 표식이다. 지우지 않는다.
4. **미태깅 영역엔 역할을 채워 넣는다** — 확신이 있을 때만. 페이지가 점점 더 읽기 쉬워진다.

### 구조 props — 크기와 배치 (실제 CSS 로 방출된다)

- `_widthMode`: `fill`(채우기) · `hug`(내용에 맞춤) · `fixed`(고정)
- `_width`: `"264px"` · `"1/4"` · `"23%"` 세 형태를 받는다
- `_height` · `_alignSelf`(`start|center|end|stretch`) · `_padding`
- 부모가 `Grid` 일 때만: `_colSpan` · `_gridColStart` · `_gridRow`

> **자유 x/y 좌표는 없다.** 전부 흐름(flow) 기반이다. 절대좌표를 허용하면 페이지끼리 정렬이
> 어긋나고 화면 크기가 바뀔 때 무엇을 어떻게 옮길지 아무도 답할 수 없다.

### 루트 props

`pageSize` — `"fhd"`(1920×1080) 또는 `"qhd"`(2560×1440). 미리보기 캔버스 크기가 된다.

## 2. 도구

```bash
npx ie page list                    # 페이지 목록
npx ie page get <slug>              # {version, title, data} — version 을 기억한다
npx ie page history <slug>          # 편집 이력
npx ie page catalog                 # 조립 가능한 컴포넌트 + **props 스키마**(데모 보유 = 렌더 가능)
npx ie page catalog --all           # 전체(렌더 불가 포함 — 노드로 쓰지 말 것)
npx ie page create "<제목>"          # 빈 페이지 → {slug, version}
npx ie page set <slug> <file.json> --base <version> --action refined --note "<한 일>"
npx ie page versions <slug>         # 스냅샷 목록
```

`set` 입력 파일 형식: `{ "title"?: string, "data": <PageData> }`

---

## 3. 주 경로 — 설명만으로 조립하고 다듬는다

1. **페이지가 없으면**: `create "<제목>"` → 설명을 바탕으로 뼈대를 조립한다(레이아웃 컨테이너 +
   자리 `Placeholder` + 맞는 레지스트리 컴포넌트) → `set … --action refined --note "초안 조립"`.
2. **이미 있으면**: `get <slug>` 로 현재 `{version, data}` 를 받고 **version 을 기억**한다.
   `history` 로 그간 이력도 참고한다.
3. `catalog` 로 후보를 확인하고 `data` 를 개선한다:
   - `여기에 …` Placeholder 를 의도에 맞는 실제 컴포넌트로 치환
   - 구조·간격 정리, 섹션 추가, `Heading`/`Text` 로 1차 콘텐츠
   - **기존 노드의 `id` 는 보존**, 새 노드만 새 id
4. `set <slug> <tmp> --base <기억한 version> --action refined --note "<무엇을 채웠는지>"`
   - **저장 전에 구조가 검증된다.** id 누락·중복, 자식을 `items` 가 아닌 곳에 둔 것, 레지스트리에
     없는 컴포넌트 이름은 **저장되지 않고 거부된다**(종료코드 65). 고친 뒤 다시 저장한다.
     이 셋은 저장은 되면서 화면만 조용히 비는 종류라, 통과시키면 사람이 나중에 발견하게 된다.
   - **종료코드 4(충돌)**: 그 사이 사람이나 다른 에이전트가 저장했다. `get` 으로 최신본을 다시 받아
     **내 변경을 재적용**한 뒤 다시 시도한다. **덮어쓰지 않는다.**
   - 이미 저장된 페이지를 점검하려면 `npx ie page check <slug>`.
5. §6 딥링크를 출력하고 브라우저로 검수한다.

---

## 4. 컴포넌트 선택 규칙

- `catalog` 의 `category`·`summary`·`keywords` 를 요구와 매칭한다. 여러 후보면 `Composite`(완성형) 우선.
- **`hasDemo:false` 는 노드 type 으로 쓰지 않는다** — 렌더할 수 없어 "미해결 컴포넌트" 로 격하된다.
  확신이 낮으면 `Placeholder` 로 두고 라벨에 의도를 남긴다(`"여기에 추이 차트"`).
- **props 를 채우는 게 정상 경로다.** 엔트리에 props 스키마가 있고 노드가 실제 props 를 들고 있으면
  미리보기가 **실 컴포넌트에 그 props 를 넘겨** 그린다. 비워 두면 데모로 폴백해 리뷰어가 결과를
  볼 수 없다. `open` 처럼 표시를 제어하는 prop 은 켜 줘야 그려진다.

---

## 5. 리뷰 피드백을 반영할 때

플레이그라운드에서 복사한 프롬프트에는 대상 페이지·현재 구조·노드 경로·저장 절차가 이미 실려 있다.

1. `get <slug>` 로 최신 `version` 을 받는다(프롬프트의 버전은 그 사이 낡았을 수 있다).
2. 피드백을 항목별로 반영한다. **지목된 노드 id 를 그대로 찾아** 그 자리에서 고친다.
3. `set … --action refined --note "리뷰 피드백 반영"`.
4. 사용자에게 **갤러리에서 피드백을 비우라고** 알린다 — 남겨 두면 다음 리뷰에서 처리된 건이 다시 섞인다.

## 6. 딥링크 + 브라우저 검수 (건너뛰지 말 것)

먼저 **지금 뜬 갤러리가 내 프로젝트의 갤러리인지** 확인한다. 같은 포트를 다른 프로젝트의 갤러리가
점유하고 있을 수 있고, 그때 오는 응답은 내 프로젝트와 아무 상관이 없다:

```bash
npx ie gallery status
```

- `✓` 면 링크를 전달하고 **실제 브라우저로 열어** 렌더를 확인한다(빈 화면·깨진 노드·엉뚱한 컴포넌트).
- `✗ 다른 갤러리가 쓰고 있습니다` → 그 포트의 응답을 근거로 삼지 않는다. `ie gallery --port <다른포트>`.
- `! 실행 중이 아닙니다` → `npx ie gallery` 를 안내하고, 링크는 **"미검증"** 이라고 명시한다.

```
http://127.0.0.1:<port>/pages/<slug>
```

포트는 `npx ie config --json` 의 `gallery.port`. 미리보기 우상단 **라이브** 모드로 봐야 레지스트리
컴포넌트가 실제 모습으로 그려진다(최소·요약은 구조만).

**스킬은 갤러리를 백그라운드로 띄우지 않는다.**

## 7. 가드레일

- 페이지 파일 **외 수정 금지**. 레지스트리·컴포넌트 코드는 읽기만.
- 모든 노드 `props.id` 유일. 컨테이너 자식은 반드시 `props.items`. — `ie page set` 이 강제한다.
- 색·간격은 프리미티브와 컴포넌트가 `st-*` 토큰으로 처리한다 — 페이지 데이터에 임의 hex·px 를
  넣지 않는다.
- **큰 삭제는 사람에게 확인**한다. 일상적인 조립·개선·저장은 자동으로 진행한다.
- `_locked` 노드는 구조를 바꾸지 않는다. 꼭 필요하면 사용자에게 확인한다.

## 8. 알려진 한계

- 3D·무거운 데모를 한 페이지에 여럿 얹으면 일부가 빈칸이 될 수 있다(에러 경계로 페이지는 유지).
- 미리보기는 **고정 크기 캔버스** 안에서 1:1 로 그려진다. 축소하지 않는 이유는 포털로 빠져나가는
  컴포넌트(모달·팝오버)가 스케일 밖에 그려져 어긋나기 때문이다.
- 프레임 전환(FHD↔QHD)은 저장되지 않는다 — 진실은 페이지의 `root.props.pageSize` 다.
