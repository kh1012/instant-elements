# 갤러리 — 의존성 기준

이 폴더는 `ie gallery` 가 Vite dev 서버로 띄우는 화면이다. `package.json` 의 `exports` 에
없으므로 **소비자 앱이 import 할 수 없고, 소비자 프로덕션 번들에도 들어가지 않는다.**

## 규칙 둘 — 서로 다른 이야기다

### 1. 소비 프로젝트의 컴포넌트 라이브러리는 쓰지 않는다 (예외 없음)

갤러리가 소비자 컴포넌트를 쓰기 시작하면 **"갤러리가 깨져서 컴포넌트를 못 보는" 순환**이
생긴다. 컴포넌트를 고치려고 여는 도구가 그 컴포넌트 때문에 안 뜨면 고칠 수단이 사라진다.

이건 **순환에 대한 규칙**이지 서드파티 의존 일반에 대한 규칙이 아니다. 소비자 것이 아닌
부품은 이 고리에 들어가지 않는다.

### 2. 서드파티 런타임 의존은 비용-편익으로 판단한다

기본은 "직접 만든다". 갤러리가 쓰는 아이콘은 손에 꼽고, 실행 로그는 커서 제어가 필요한
셸 화면이 아니라 append-only 목록이다 — 그런 것에 라이브러리를 들이면 **얻는 것보다 치르는
것이 크다.**

들이는 기준은 하나다: **제대로 만들려면 그 자체가 프로젝트가 되는 것.**

| | 판단 | 이유 |
|---|---|---|
| 아이콘 | 직접 그린다 | 하나가 10줄 |
| 터미널 에뮬레이터 | 직접 만든다 | 스크롤되는 목록이면 충분 |
| 툴팁·팝오버·다이얼로그 | 직접 만든다 | 포털 + Esc + 바깥클릭이면 끝 |
| 마크다운 파서 | 직접 만든다 | 코드펜스와 URL 둘만 필요 |
| **그래프 뷰포트**(`@xyflow/react`) | **들인다** | pan/zoom·드래그 배선·엣지 라우팅·뷰포트 맞춤은 각각이 다시 하나의 프로젝트다 |

## 지금 들어와 있는 것

- `@xyflow/react` — 흐름 지도 전용. **동적 import** 로 불러온다(`FlowMap.tsx`).
  컴포넌트 갤러리만 보는 사람의 첫 로딩에 1.9MB 가 딸려오면 안 된다.

설치 용량은 +1.9MB 이고, 이 패키지는 이미 vite(2.3MB)·jiti(1.7MB)를 함께 설치한다.
소비자 프로덕션 번들 영향은 0이다.
